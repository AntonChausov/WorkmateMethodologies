# 08. Итерация до критерия с независимым ревью

**Источники:** Ralph Wiggum loop (повторять до объективного критерия), Superpowers `verification-before-completion` (никакого «готово» без доказательства); подзадача-ревьюер с чистым контекстом.

## Идея

1. **Критерии готовности до правок** — проверяемые утверждения о результате (плюс «нет ошибок EDT», «изменено только нужное»); человек подтверждает.
2. **Цикл (не больше 5 итераций):** сделать → маркеры EDT → одна подзадача-ревьюер, которой передают только критерии и список измененных объектов (вердикт по умолчанию «опровергнуто», цитата файл:строка, попытка контрпримера, лишние изменения) → выход только при всех «подтверждено».
3. **Отчет:** «готово» — только если подтверждены все критерии; непрогнанные тесты так и называются.

Внешний цикл Ralph (перезапуск агента извне) в Напарнике невозможен — цикл идет внутри одного диалога.

## Что внутри

| Файл | Назначение |
|---|---|
| `.workmate/commands/довести.md` | `/довести <задача или ссылка на план/спецификацию>` (v1) |

**Уровень установки:** любой.

## Как пользоваться

1. Режим «Агент»: `/довести <задача>`; проверьте и подтвердите критерии.
2. Прочитайте отчет-таблицу «критерий / вердикт ревьюера / доказательство / итерация».
3. **Запустите тесты YAxUnit сами** и, если что-то упало, отдайте результат агенту следующим сообщением.

## Что показал эксперимент

Задача «Срок действия билета» (константа, запрет посещения просроченного билета, 4 автотеста), независимая проверка по 11 критериям и прогон тестов:

| | Без методики | `/довести` |
|---|---|---|
| Время / контекст | 18 мин / 47,5% | 7 мин / 39,3% |
| Дефект кода (переполнение в конструкторе `Дата()`) | есть | нет |
| Ловушка YAxUnit (запрос после исключения в `ВТранзакции()`) | есть | есть |
| Тесты при независимом прогоне | 3/4 | 3/4 |
| Ложное «готово» | да | частично (оговорка «тесты не запускались», но «доведено») |
| Итераций цикла | — | 1 |

- Дисциплина работает: критерии до правок, отчет с цитатами, быстрее и дешевле по контексту, честнее про непрогнанные тесты.
- **Цикл вырождается без объективного сигнала.** Напарник не запускает тесты, единственный объективный критерий — маркеры EDT; ревьюер по коду подтвердил все с первой итерации и не увидел ошибку времени выполнения в тесте.

### Перепроверка версии 1.2 (21.10.2026, та же задача, режим «Агент», уровень проекта, 1С:Напарник 1.0.8)

Тесты после каждого отчета запускал человек (EDT) и передавал результат агенту следующим сообщением.

| Итерация | Что сделал агент | Прогон тестов | Статус отчета |
|---|---|---|---|
| 1 | константа, проверка срока, 4 теста; ревьюер подтвердил все критерии «структурно» | 0/4 — клиент не записывается (справочник требует телефон) | `ОЖИДАЕТ ПРОГОНА ТЕСТОВ` |
| 2 | сам нашел причину, клиент — `Записать(Ложь, Истина)` | 3/4 — тест 4 проверял `ДокументОбъект.Проведен` (флаг в памяти остается `Истина` после отказа) | `ОЖИДАЕТ ПРОГОНА ТЕСТОВ` |
| 3 | проверка состояния базы запросом | 3/4 — «В данной транзакции уже происходили ошибки!» (запрос после исключения в `ВТранзакции()`) | `ОЖИДАЕТ ПРОГОНА ТЕСТОВ` |
| 4 | тест 4 вне транзакции, удаление тестовых данных, восстановление константы | **4/4**; мутация (проверка срока отключена) — тест 4 падает | `ОЖИДАЕТ ПРОГОНА ТЕСТОВ` |
| 5 | «изменено только нужное» — по `git diff HEAD` | — | **`ДОВЕДЕНО`** |

- **Правки версии 1.1 работают:** три статуса — ни одного ложного «доведено» при непрогнанных тестах; результат прогона, переданный после отчета, запускает следующую итерацию (п. 4 команды).
- **С объективным сигналом цикл сходится.** Все три ловушки тестов агент устранил сам, без подсказок; код проверки срока был верным с итерации 1 (`НачалоДня`, N − 1, отказ до движений). Ревьюер по коду ошибки времени выполнения в тестах не увидел ни разу — сигнал дал только прогон.
- **Критерий от человека пригодился:** при подтверждении критериев добавлен «календарные дни независимо от времени документов (30.10 23:59:59 — да, 31.10 00:00 — нет)»; тесты на него написаны.
- **Ложные срабатывания «изменено только нужное»:** ревьюер (итерация 2) и агент (итерация 5) сравнивали модуль с локальной историей EDT и сочли «удаленным» код, которого нет в последнем коммите. Снято указанием сравнивать с `git diff HEAD`.
- Время и контекст: около 23 мин на итерацию, контекст до 67%.

## Ограничения

- До появления в Напарнике запуска тестов — запускайте их сами и возвращайте результат агенту.
- В версии 1.1 отчет заканчивается строкой статуса из трех значений: `ДОВЕДЕНО` / `ОЖИДАЕТ ПРОГОНА ТЕСТОВ` / `НЕ ДОВЕДЕНО` — против «доведено» при непрогнанных тестах; в режиме «Планирование» файлы попадают в план отдельными пунктами. Правки версии 1.1 проверены прогоном в версии 1.2 (см. выше).
- Проверку «изменены только нужные объекты» делайте по `git diff HEAD`: локальная история EDT дает ложные «удаления» (см. перепроверку 1.2).
