Сформируй спецификацию изменения в стиле OpenSpec. Идея/название изменения: {{ARGUMENTS}}

Создай папку openspec/changes/<слаг>/ (слаг — ASCII kebab-case из названия) и файлы:
- proposal.md — зачем делаем, что меняется, границы (что входит и что не входит);
- specs/ — требования: заголовки `## ADDED Requirements`, затем `### Requirement: <название>`
  и сценарии `#### Scenario: <название>` с пунктами **WHEN** / **THEN**;
- design.md — технический подход, затрагиваемые объекты, альтернативы;
- tasks.md — чек-лист задач с чекбоксами `- [ ]`.

Требования и сценарии формулируй по references/ears-i-scenarii.md навыка
«Работа со спецификациями»: через ДОЛЖНО, одна проверяемая реакция на требование,
конкретные значения и опорная дата в сценариях.

В файл спеки добавь раздел `## Граничные случаи`: по КАЖДОМУ пункту чек-листа из
references/ears-i-scenarii.md — одна строка вида «покрыт сценарием <имя>» /
«неприменим: <почему>» / «ручная проверка: <почему>». Пункт без строки — спека не готова.
