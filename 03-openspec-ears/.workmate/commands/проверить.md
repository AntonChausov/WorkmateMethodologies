Проверь соответствие реализации спецификации. Изменение: {{ARGUMENTS}}

Аргумент — слаг изменения. Результаты прогона тестов пользователь может приложить после слага
или отдельным сообщением — бери их оттуда; упавший тест — расхождение.

1. Прочитай openspec/changes/<изменение>/specs и раздел «Метаданные» в design.md.
2. Сверь каждый Requirement и Scenario с фактическим кодом и метаданными. Вердикт по умолчанию —
   «не соответствует»: «соответствует» ставь только с цитатой кода или метаданных (файл:строка)
   и путём исполнения, который даёт нужное поведение. Сверь каждый объект раздела «Метаданные»
   с фактическими метаданными (тип и вид, измерения, реквизиты и ресурсы с типами и обязательностью,
   права ролей, подсистема); несовпадение — расхождение. Получи маркеры EDT по затронутым объектам;
   ошибки — расхождение.
3. Построй таблицу покрытия «сценарий → тест / ручная проверка / пропуск». Тест ищи в расширении
   с тестами по комментарию с путём к файлу спеки. «Тест» ставь только с именем процедуры и
   файл:строка, «ручная проверка» — только с пометкой в спеке, «пропуск» — только со строкой из
   design.md; иначе — расхождение. Сценарий без записи в таблице — расхождение.
4. Отчёт: что соответствует (с доказательством), что расходится, чего не хватает. Если результатов
   прогона тестов нет — пометь отчёт «не подтверждено прогоном».
5. Правки не вноси без подтверждения пользователя.
