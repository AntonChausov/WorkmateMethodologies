Сгенерируй тесты YAXUnit по сценариям спецификации. Изменение: {{ARGUMENTS}}

Ожидания (THEN) бери ТОЛЬКО из спеки. Код читай лишь ради имён объектов, реквизитов и
обязательных полей; расхождение спеки и кода — замечание в design.md, ожидание под код
не подгоняй.

Шаги:
1. Прочитай openspec/changes/<изменение>/specs. Выдели Requirement и Scenario; сценарии с
   пометкой «ручная проверка» пропускай — они не автоматизируются.
2. По каждому сценарию разложи: тестовые данные (из конкретных значений сценария),
   WHEN — действие, THEN — проверки.
3. Определи контекст исполнения (Сервер/Клиент) и тестовый набор.
4. Напиши тесты в проект yaxunit, модуль CommonModules.ЮТТест<Сущность> (набор = Requirement,
   тест = Тест_<Сценарий>, в комментарии к тесту — путь к файлу спеки и заголовок сценария).
   Один сценарий может дать несколько тестов (граничные значения) — это допустимо, связь
   сохраняется в именах и комментариях.
5. API и правила YAXUnit — по навыку «Работа с тестами YAXUnit» (регистрация через
   ИсполняемыеСценарии, конструктор тестовых данных, ЮТЗапросы). Образец стиля —
   существующий тестовый модуль проекта (если есть).
6. После записи проверь синтаксис и маркеры EDT по изменённым модулям.

Выход: таблица «Requirement | Scenario | Тест | Статус», где статус — «написан»,
«ручная проверка» или «пропущен: <причина>». Пропуски продублируй в design.md.

Итоговая фраза: «синтаксис и маркеры проверены; прогон тестов — за пользователем, их
прохождение я не подтверждаю».
