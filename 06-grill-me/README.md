# 06. Интервью по постановке (grill me)

**Источник:** Matt Pocock, навык `grill-me` → `grilling`.

## Идея

Перед проектированием агент дотошно расспрашивает о задаче, пока не наступит общее понимание. Решения образуют **дерево**; каждым раундом агент задает весь «фронт» — вопросы, у которых уже решены все предпосылки, — с номером и **рекомендуемым ответом**. Факты (какие объекты, реквизиты, движения, как работает код) агент ищет **сам**, решения оставляет человеку. Интервью закончено, когда фронт пуст.

Адаптация к Напарнику: явный вызов командой (не автонавык — иначе агент допрашивал бы на каждой задаче); факты — подзадачей `explore`; если ответ противоречит коду — агент говорит об этом; каждое найденное в коде ограничение (лимиты, контроли, связанные начисления) — отдельная ветка дерева; итог сохраняется планом.

## Что внутри

| Файл | Назначение |
|---|---|
| `.workmate/commands/расспроси.md` | `/расспроси <задача>` (v2) |

**Уровень установки:** любой.

## Как пользоваться

1. Новый диалог, режим **«Планирование»**: `/расспроси <задача в одну-две фразы>`.
2. Отвечайте на раунды; «да» — согласие с рекомендацией.
3. На вопрос «Достигнуто ли общее понимание?» ответьте «да» — итог сохранится планом Напарника (решения, факты, допущения, вне рамок, риски, шаги).
4. **Проверьте план** и начните реализацию в новом диалоге по нему.

## Что показал эксперимент

Задача «Нужно сделать возврат билетов», эталон — 13 решений:

| Вариант | Решений вскрыто | Контекст |
|---|---|---|
| Без методики («задай уточняющие вопросы») | 8,5 | 39,5% |
| `/расспроси` v1 | 10,5 | 22,5% |
| `/расспроси` v2 | 11 | 21,2% |

- Даже без методики Напарник ищет факты сам и задает вопросы раундами — часть методики уже встроена. Методика добавляет **глубину**: «а если баллы уже потрачены», «как делится возврат при оплате баллами»; права и филиал перестают приниматься молча.
- Сработала сверка ответа с кодом: на ответ, противоречащий модели данных, агент перечитал регистры и вынес отдельный вопрос.
- Предел: вопросы рождаются из фактов кода. То, чего в коде нет (причина возврата, влияние на будущие начисления), не спросил ни один вариант — это знание предметной области за человеком.

### Перепроверка версии 1.2 (19–20.10.2026, та же задача «Нужно сделать возврат билетов», режим «Планирование»)

| | v2 (16.10) | v1.1 (20.10) |
|---|---|---|
| Решений эталона вскрыто | 11 из 13 | **12 из 13** (пропущен филиал — не вынесен вопросом, хотя RLS по филиалу найден) |
| Раундов / вопросов | — | 4 / 21 (В1–В21) |
| Контекст | 21,2% | 24,1% |
| Вопросов о фактах конфигурации | 0 | 0 |

- **Раунд о предметной области (новое в 1.1) сработал:** отчетность, денежный/фискальный контур, влияние возврата на будущие начисления через сумму покупок (в 16.10 не спросил никто), даты запрета изменения.
- **Сверка ответов с кодом:** после первого раунда агент нашел три конфликта решений с конфигурацией (остаток посещений по виду, а не по позиции; `Продажи` оборотный с `nonNegative` — сторно минусом невозможно; начисленные баллы не хранятся) и вынес их вопросами; ответ (б) на В19 породил зависимый В21.
- **Итог (план):** факты подтверждены с источниками и сверены — ошибок нет (в 16.10 регистры остатков были названы оборотными); раздел «Уточнить при реализации» есть. Отступления: в шагах — необсужденные реквизиты (ответственный, филиал, сумма, RLS по филиалу); два допущения не вынесены вопросом, но перечислены в «Допущения».

## Ограничения

- В режиме «Планирование» агент не пишет файлы — итог сохраняется планом.
- В плане могут появиться ошибки фактов и проектные детали, которые не обсуждались, — проверяйте. В версии 1.1 команда требует переносить в план только подтвержденные факты с источником, а необсужденные детали — в раздел «Уточнить при реализации»; добавлен раунд вопросов о предметной области, которой нет в коде. Правки версии 1.1 проверены прогоном в версии 1.2 (см. выше).
- Счетчик времени Напарника сбрасывается на каждом раунде вопросов.
