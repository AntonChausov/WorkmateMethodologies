# 05. Ревью в изолированном контексте

**Источник:** Superpowers (requesting-code-review).

## Идея

Агент, который писал код, плохо его проверяет: в контексте его же рассуждения. Ревью делает **подзадача с чистым контекстом**, которой передают только список файлов и чек-лист — без пересказа и оценок. Ключевой прием: **вердикт по умолчанию — «опровергнуто»**, пока не найдено доказательство; «подтверждено» требует цитаты; для «неприменим» строится контрпример; для каждого теста проверяется, упал бы он при поломке проверяемой ветки.

## Что внутри

| Файл | Назначение |
|---|---|
| `.workmate/commands/ревью.md` | `/ревью <слаг изменения в openspec/changes или список модулей>` — одна подзадача-ревьюер, таблица «утверждение / вердикт / доказательство / файл:строка / важность»; ничего не исправляет |

Работает и без OpenSpec: передайте список модулей. С `02`/`03` проверяет также спеку, `design.md`, `tasks.md` и покрытие сценариев.

**Уровень установки:** любой.

## Как пользоваться

После реализации, **в новом диалоге**: `/ревью <слаг>` или `/ревью Документы/X/ObjectModule.bsl, ОбщиеМодули/Y`. Опровергнутые пункты разберите и исправьте отдельной задачей.

## Что показал эксперимент

Изменение с заранее заложенными ошибками (эталон — 6 пунктов):

| Вариант | Найдено из 6 |
|---|---|
| Простой запрос «сделай ревью» | ≈1,5 |
| Чек-лист без принципа опровержения | ≈1,5 (суждения «проштампованы» подтверждением) |
| **Текущая версия (опровержение)** | **3** + находки сверх эталона |

Сверх эталона: тест, который ничего не различает (проходит и с ошибкой, и без), и непокрытый тестами отбор.

### Перепроверка версии 1.2 (19.10.2026, то же изменение `limit-biletov-na-klienta`, режим «Только чтение»)

| Прогон | Время / контекст | Найдено из 6 | Что еще |
|---|---|---|---|
| `/ревью <слаг>` №1 | 5:45 / 22% | **3** (границы чисел; двойное нажатие = повторное проведение — впервые; другой клиент) | гонка при проведении (опровергнута «ручная проверка»); оба неразличающих теста; противоречия design/tasks/код |
| `/ревью <список модулей>` при существующей спеке №2 | 4:06 / 16,9% | **1** (границы чисел) | неразличающие тесты; правила тестов проекта; другой клиент, двойное нажатие, гонка, «нет API» — подтверждены (агент нашел спеку по поиску и провел полное ревью) |
| `/ревью <список модулей>` без спеки №3 | 2:48 / 26,7% | — (эталон о спеке неприменим) | **спросил требования** (предложил восстановить из комментариев тестов или ввести свои); пункты спеки — «не проверить: нет раздела»; требования разобраны на условия — «одному клиенту» не покрыто тестами (high), оба неразличающих теста, отступления от правил проекта |

- Один промпт на одном объекте дает от 1 до 3 из 6: различающая сила тестов находится стабильно, суждения об обоснованиях («ручная проверка», «неприменим», «нет API») — нестабильно. Результат одного ревью — подсказка; для важного изменения запустите ревью дважды и объедините находки.
- Обоснование со ссылкой на авторитет «нет API» оба раза принято после проверки только документации YAxUnit (платформенный `ПолучитьСообщенияПользователю()` не рассмотрен).
- В 1.2 добавлена строка о пути `openspec/` (как в 02/03).

## Ограничения

- Ревью по коду не видит ошибок, которые проявляются только при исполнении — нужен прогон тестов. Известные ловушки фреймворка тестов опишите в правилах проекта: ревьюер учтет их через стандарты проекта.
- В версии 1.1 добавлены: обоснования со ссылкой на авторитет без проверки считаются «опровергнуто»; режим без спецификации (требования берутся из задачи или у пользователя). Проверку ловушки `ВТранзакции()` из команды убрали — это правило проекта, а не методики. Правки версии 1.1 проверены прогоном в версии 1.2 (см. выше).
