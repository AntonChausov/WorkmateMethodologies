# Инструкция для 1С:Напарника

Ты — 1С:Напарник. Пользователь дал тебе этот репозиторий, чтобы ты рассказал, что в нем, и установил выбранные методики. Выполни шаги ниже по порядку.

## Шаг 1. Прочитай репозиторий

1. Прочитай `README.md` в корне репозитория.
2. Прочитай `README.md` в каждом каталоге методики (`01-…` — `08-…`).
3. Посмотри состав папок `.workmate/` в каждом каталоге, чтобы знать, какие файлы будешь устанавливать. Содержимое файлов команд и навыков читать целиком сейчас не нужно.

Ничего не создавай и не меняй на этом шаге.

## Шаг 2. Расскажи пользователю

Коротко, своими словами:
- что это за репозиторий: известные методики ИИ-разработки, перенесенные на Напарника через команды и навыки и проверенные экспериментами;
- главные выводы экспериментов (раздел «Главное, что показали эксперименты» в README);
- список методик — по строке на каждую: название, что дает, что входит (команды/навыки), рекомендуемый уровень установки.

Отдельно предупреди:
- `02-openspec` и `03-openspec-ears` — две версии одной методики с одинаковыми именами файлов. Ставится только одна (03 — расширенная: EARS, граничные случаи, тесты по сценариям).
- Методики `01`, `02`, `03`, `07` рассчитаны на уровень **проекта**: они хранят данные проекта (стандарты, спецификации `openspec/`, глоссарий).

## Шаг 3. Спроси, что устанавливать

Спроси пользователя (инструментом вопросов, если он есть):
1. Какие методики установить — можно несколько.
2. На какой уровень:
   - **общий** — для всех рабочих областей пользователя: `%USERPROFILE%\.workmate\`;
   - **рабочая область** — для всех проектов этой рабочей области EDT: `<каталог рабочей области>\.workmate\`;
   - **проект** — для одного проекта: `<каталог проекта EDT>\.workmate\` (для проекта уточни, какого именно).

   Можно разный уровень для разных методик. Для `02`/`03` на любом уровне дополнительно спроси, в каких проектах создать папку `openspec/`. Для `01`, `02`, `03`, `07` рекомендуй уровень проекта; если пользователь выбирает другой — предупреди, что команды этих методик пишут свои данные в `.workmate/` и `openspec/` проекта, и спроси подтверждение.

Если ты знаешь из своей документации, что каталоги уровней устроены иначе, — используй их и скажи об этом пользователю.

Не начинай установку, пока пользователь не ответил.

## Шаг 4. Установи

Для каждой выбранной методики:

1. Скопируй каждый файл из `<каталог методики>/.workmate/` в `.workmate/` выбранного уровня с той же относительной структурой (`commands/<имя>.md`, `skills/<slug>/SKILL.md`, `skills/<slug>/references/...`).
2. Копируй **дословно**: не сокращай, не переформулируй, не «улучшай» тексты, не меняй кодировку и имена файлов. Ты переносишь проверенные тексты.
3. Если файл с таким именем уже существует — не перезаписывай молча: покажи пользователю, чем файлы различаются, и спроси, заменить ли.
4. Для `02-openspec` или `03-openspec-ears` дополнительно: в каждом проекте, который назвал пользователь, создай в корне проекта EDT (рядом с папкой `src`) папку `openspec/` с подпапками `specs/` и `changes/archive/` и скопируй туда `openspec/README.md` из каталога методики. Если `openspec/` уже есть — не трогай существующие файлы, только добавь недостающее.
5. Файлы правил `WORKMATE.md` не меняй.

## Шаг 5. Отчитайся

0. Сначала сверь копии: перечитай каждый созданный файл и сравни с исходным число строк и последнюю строку. При расхождении скопируй файл заново и сверь еще раз.
1. Перечисли, что установлено: методика → уровень → полный путь каждого созданного файла.
2. Перечисли, что пропущено и почему (например, пользователь отказался заменять существующий файл).
3. Напомни:
   - новые навыки станут видны **только в новом диалоге** — открой новый диалог перед использованием;
   - как начать работу с каждой установленной методикой — первая команда из раздела «Как пользоваться» ее README.
   - если установлена `07-glossariy` — отдельно предупреди: сам по себе навык глоссария подключается ненадежно, поэтому в постановке задачи нужно явно ссылаться на глоссарий («…сверь термины задачи с глоссарием…») или один раз добавить в правила проекта (`WORKMATE.md`) строку из п. 3 раздела «Как пользоваться» README методики. Покажи эту строку дословно и предложи пользователю добавить ее самому; `WORKMATE.md` сам не меняй.
