# 01. Стандарты проекта с автоизвлечением из кода

**Источник:** Agent OS (Discover Standards), Spec Kit (constitution), Kiro (steering).

## Идея

У каждой живой конфигурации есть свои соглашения: как пишутся запросы, как устроены модули, какие механизмы БСП приняты. Агент о них не знает и пишет «как в среднем по интернету». Методика: агент сам извлекает соглашения из существующего кода в черновик, **человек утверждает**, утвержденное становится навыком, который агент читает перед написанием кода.

## Что внутри

| Файл | Назначение |
|---|---|
| `.workmate/commands/извлечь-стандарты.md` | `/извлечь-стандарты <область>[, объект или подсистема]` — охват, обход модулей подзадачами, черновик правил и реестр отклонений в `.workmate/standards/` |
| `.workmate/commands/принять-стандарты.md` | `/принять-стандарты <область>` — переносит правила со статусом «утверждено» в навык `standarty-proekta` (создает его при первом запуске) |

Области: `модули`, `запросы`, `бсп`, `формы`. Навык `.workmate/skills/standarty-proekta/` в репозитории не лежит — его создает `/принять-стандарты` из ваших утвержденных правил.

**Уровень установки:** проект (стандарты — свойство конкретной конфигурации).

## Как пользоваться

1. Новый диалог, режим «Агент»: `/извлечь-стандарты запросы` (для большой конфигурации сузьте охват: `/извлечь-стандарты модули, Продажи`).
2. **Выверьте черновик руками:** `.workmate/standards/черновик-<область>.md`. Удалите лишнее, исправьте формулировки, нужным правилам поставьте `**Статус:** утверждено`. Это обязательный шаг.
3. Новый диалог: `/принять-стандарты запросы` — покажет, что перенесет, и попросит подтверждение.
4. Дальше в новых диалогах навык подгружается сам перед написанием кода.

## Что показал эксперимент

- Охват, обход модулей и подсчет мест надежны: списки объектов и счетчики совпали с независимой проверкой, найдены реальные дефекты вне известной карты дефектов.
- Суждения — слабо: правила, которые на самом деле являются общим стандартом ИТС, помечались «спецификой проекта»; модули с ошибками попадали в доказательства; из отсутствия конструкции выводилось «правило»; порог «≥ 3 места в ≥ 2 объектах» применялся неверно. Из ~7 правил черновика после выверки утверждено одно.
- `/принять-стандарты` работает чисто: переносит только утвержденное, спрашивает подтверждение, сокращает доказательства.
- Навык подгружается до записи кода (проверено на задаче с запросом).
- Подзадачи типа `explore` только читают — запись в файл сбора идет из подзадач, которым агент дал право записи; иначе находки копятся в основном диалоге.
- Польза навыка на правиле, которое меняет поведение агента по сравнению с «умолчанием», отдельно не измерялась.

- `/принять-стандарты` без утвержденных правил останавливается и ничего не пишет; после выверки переносит только утвержденное, с подтверждением.
- **Навык меняет поведение:** в задаче «добавь печать по образцу `ПечатьРекламы`» (в образце — `Запрос.Параметры.Вставить`) агент прочитал `references/запросы.md` до записи кода и написал `Запрос.УстановитьПараметр` — по стандарту проекта, а не по локальному образцу.

## Ограничения и известные доработки

- Выверка человеком обязательна — без нее в навык попадут ложные правила.
- Команда упоминает инструменты Напарника (`1C_Find`, `GetObject_in_Project`, поиск по ИТС); если инструмента нет, агент использует доступный аналог.
- В версии 1.1 добавлены: пишущие подзадачи для файла сбора; поиск отклонений по реальной альтернативе паттерна; исключение правил, которые ИТС требует или рекомендует; запрет выводить правило из отсутствия конструкции; нарушения общего стандарта — в реестр отклонений. Правки версии 1.1 прогоном не проверялись. Версия 1.2 (перепроверка прогоном, см. выше): пути относительно каталога проекта; полный охват (все объекты `src` минус `СтандартныеПодсистемы`, сверка по каталогам `src/`); N и M — поиском по коду с построчной сверкой примеров; «общий стандарт» — только v8std и документация БСП; области названы по-русски (`запросы`, `модули`, `бсп`, `формы`).
- Известное: полный охват дорог по времени (≈ 30 мин на конфигурацию с БСП); счетчики одного правила агент может скопировать из соседнего — проверяйте при выверке; тривиальные «правила» без реальной альтернативы в проекте отсеивайте вручную.
